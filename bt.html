Core Concepts

Utility-First vs Component Classes

Bootstrap gives you pre-built components (.card, .navbar). Tailwind gives you primitive utilities you compose together.

<!-- Bootstrap -->
<div class="card shadow-sm">
  <div class="card-body">
    <h5 class="card-title">Card</h5>
    <p class="card-text">Content</p>
  </div>
</div>

<!-- Tailwind â€” same result, built from utilities -->
<div class="bg-white rounded-xl shadow-md overflow-hidden">
  <div class="p-6">
    <h2 class="text-xl font-semibold text-gray-900">Card</h2>
    <p class="mt-2 text-gray-600">Content</p>
  </div>
</div>
Mindset shift: Instead of searching for "the right BS class", you compose tiny single-purpose classes. .card (1 class) â†’ bg-white rounded-xl shadow-md overflow-hidden (4 classes).
Responsive & State Variants

Like Bootstrap's breakpoint prefixes (.col-md-6), Tailwind uses prefixes on any utility:

<!-- Bootstrap -->
<div class="col-12 col-md-6 col-lg-4">...</div>

<!-- Tailwind -->
<div class="w-full md:w-1/2 lg:w-1/3">...</div>

<!-- State variants work on ANY class -->
<button class="bg-blue-600 hover:bg-blue-700 focus:ring-2
               active:scale-95 disabled:opacity-50">
  Click
</button>

<!-- Group hover (BS doesn't have this) -->
<div class="group">
  <h3 class="group-hover:text-blue-600">Title</h3>
</div>
Key difference: In BS, hover: only works on some components. In Tailwind, every utility gets every variant: sm:md:lg:xl:2xl:, hover:focus:active:visited:disabled:, dark:print:portrait:landscape:, group-hover:peer-checked:, and custom ones via @custom-variant.

Customization

CSS-First Config via @theme (v4)

Bootstrap uses --bs-* CSS vars or SASS. Tailwind v4 uses the @theme directive â€” no config file needed.

@import "tailwindcss";

@theme {
  /* Colors â€” like --bs-primary */
  --color-primary: #ff6600;
  --color-primary-dark: #cc5200;

  /* Spacing â€” extend the scale */
  --spacing-18: 4.5rem;

  /* Fonts */
  --font-family-display: 'Cinzel', serif;

  /* Border radius */
  --radius-4xl: 2rem;

  /* Shadows */
  --shadow-glow: 0 0 20px rgba(255, 102, 0, 0.3);

  /* Breakpoints */
  --breakpoint-3xl: 2000px;
}

/* Then use anywhere: bg-primary, font-display, shadow-glow */
@apply & Layers (like BS component classes)

Use @apply to create Bootstrap-style component classes from utilities:

@layer components {
  .btn-primary {
    @apply inline-flex items-center px-4 py-2
           bg-blue-600 text-white font-medium text-sm
           rounded-lg hover:bg-blue-700
           transition-colors duration-200;
  }

  .card-bs {
    @apply bg-white rounded-xl shadow-md overflow-hidden;
  }

  .card-body {
    @apply p-6;
  }
}

@layer base {
  h1 { @apply text-4xl font-bold tracking-tight; }
  body { @apply antialiased text-gray-900; }
}

@layer utilities {
  .text-balance { text-wrap: balance; }
}
BS â†’ TW: BS gives you .btn-primary out of the box. Tailwind makes you define it yourself via @apply. More work upfront, but you control everything â€” no "Bootstrap look" limitation.
