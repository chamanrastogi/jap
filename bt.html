Core Concepts

Utility-First vs Component Classes

Bootstrap gives you pre-built components (.card, .navbar). Tailwind gives you primitive utilities you compose together.

<!-- Bootstrap -->
<div class="card shadow-sm">
  <div class="card-body">
    <h5 class="card-title">Card</h5>
    <p class="card-text">Content</p>
  </div>
</div>

<!-- Tailwind — same result, built from utilities -->
<div class="bg-white rounded-xl shadow-md overflow-hidden">
  <div class="p-6">
    <h2 class="text-xl font-semibold text-gray-900">Card</h2>
    <p class="mt-2 text-gray-600">Content</p>
  </div>
</div>
Mindset shift: Instead of searching for "the right BS class", you compose tiny single-purpose classes. .card (1 class) → bg-white rounded-xl shadow-md overflow-hidden (4 classes).
Responsive & State Variants

Like Bootstrap's breakpoint prefixes (.col-md-6), Tailwind uses prefixes on any utility:

<!-- Bootstrap -->
<div class="col-12 col-md-6 col-lg-4">...</div>

<!-- Tailwind -->
<div class="w-full md:w-1/2 lg:w-1/3">...</div>

<!-- State variants work on ANY class -->
<button class="bg-blue-600 hover:bg-blue-700 focus:ring-2
               active:scale-95 disabled:opacity-50">
  Click
</button>

<!-- Group hover (BS doesn't have this) -->
<div class="group">
  <h3 class="group-hover:text-blue-600">Title</h3>
</div>
Key difference: In BS, hover: only works on some components. In Tailwind, every utility gets every variant: sm:md:lg:xl:2xl:, hover:focus:active:visited:disabled:, dark:print:portrait:landscape:, group-hover:peer-checked:, and custom ones via @custom-variant.

Layout

Grid System

Bootstrap's 12-column grid becomes Tailwind's grid-cols-*:

<!-- Bootstrap: 3 equal columns with gap -->
<div class="container">
  <div class="row g-4">
    <div class="col-md-4">Column 1</div>
    <div class="col-md-4">Column 2</div>
    <div class="col-md-4">Column 3</div>
  </div>
</div>

<!-- Tailwind: same layout -->
<div class="container mx-auto max-w-7xl px-4">
  <div class="grid grid-cols-1 md:grid-cols-3 gap-4">
    <div>Column 1</div>
    <div>Column 2</div>
    <div>Column 3</div>
  </div>
</div>

<!-- Mixed column widths (12-col style) -->
<div class="grid grid-cols-12 gap-4">
  <div class="col-span-12 md:col-span-8">Main</div>
  <div class="col-span-12 md:col-span-4">Sidebar</div>
</div>
Flexbox alternative: flex flex-wrap gap-4 with w-1/3 works too — more like BS row/col.
BS → TW: .container = container mx-auto max-w-7xl (or max-w-6xl). .row = grid grid-cols-12 gap-4 (or flex flex-wrap). .col-md-4 = md:col-span-4.

Spacing & Sizing

Margin, Padding, Gap

Good news: Tailwind uses the same scale as Bootstrap (0–5 = 0–3rem).

<!-- Identical syntax -->
.m-0 / .m-1 / .m-2 / .m-3 / .m-4 / .m-5    /* 0–3rem */
.p-0 / .p-1 / .p-2 / .p-3 / .p-4 / .p-5
.mt- / .mb- / .ml- / .mr- / .pt- / .pb- / .pl- / .pr-

<!-- EXCEPT Tailwind uses 's' not 's' for start/end -->
.ps-3 = .pl-3 (or .ms-3 for margin-inline-start)
.pe-3 = .pr-3
.ms-auto                              /* margin-left: auto */
.mx-auto                              /* center block */

<!-- Gap (same as BS .g-*) -->
.gap-2 / .gap-4 / .gap-x-6 / .gap-y-8

<!-- Space between children (BS doesn't have) -->
.space-y-4 / .space-x-4

<!-- Extra values BS doesn't have -->
.p-6 (1.5rem) / .p-8 (2rem) / .p-10 (2.5rem) / .p-12 (3rem)
.p-16 (4rem) / .p-20 (5rem) / .p-24 (6rem)

<!-- Arbitrary -->
.p-[17px] / .mt-[calc(100vh-80px)]
BS → TW: The spacing scale 0–5 is identical. Tailwind adds 6, 8, 10, 12, 14, 16, 20, 24, 28, 32, 36, 40, 44, 48, 52, 56, 60, 64, 72, 80, 96. So .mt-3 works in both — you already know it.

Tailwind Color Palette

Bootstrap has 8 named colors (primary, secondary, success, danger, warning, info, light, dark). Tailwind has 22 color families, each with 10–11 shades (50–950).

Dark Mode

Dark Variant

Bootstrap uses data-bs-theme="dark". Tailwind uses the dark: prefix with a class on <html>.

<!-- Bootstrap -->
<html data-bs-theme="dark">
<div class="bg-dark text-light">Dark section</div>

<!-- Tailwind -->
<html class="dark">
<div class="bg-gray-900 text-gray-100 dark:bg-black dark:text-white">
  Dark section
</div>

<!-- Every utility can be toggled -->
<div class="bg-white dark:bg-gray-800
            text-gray-900 dark:text-gray-100
            border border-gray-200 dark:border-gray-700
            shadow-md dark:shadow-none">
  Theme-aware card
</div>

<!-- JS toggle -->
document.documentElement.classList.toggle('dark');
localStorage.setItem('theme', 'dark');
Key difference: BS's dark mode is opt-in per component (data-bs-theme overrides). Tailwind's dark: lets you toggle individual properties — much finer control.

Customization

CSS-First Config via @theme (v4)

Bootstrap uses --bs-* CSS vars or SASS. Tailwind v4 uses the @theme directive — no config file needed.

@import "tailwindcss";

@theme {
  /* Colors — like --bs-primary */
  --color-primary: #ff6600;
  --color-primary-dark: #cc5200;

  /* Spacing — extend the scale */
  --spacing-18: 4.5rem;

  /* Fonts */
  --font-family-display: 'Cinzel', serif;

  /* Border radius */
  --radius-4xl: 2rem;

  /* Shadows */
  --shadow-glow: 0 0 20px rgba(255, 102, 0, 0.3);

  /* Breakpoints */
  --breakpoint-3xl: 2000px;
}

/* Then use anywhere: bg-primary, font-display, shadow-glow */
@apply & Layers (like BS component classes)

Use @apply to create Bootstrap-style component classes from utilities:

@layer components {
  .btn-primary {
    @apply inline-flex items-center px-4 py-2
           bg-blue-600 text-white font-medium text-sm
           rounded-lg hover:bg-blue-700
           transition-colors duration-200;
  }

  .card-bs {
    @apply bg-white rounded-xl shadow-md overflow-hidden;
  }

  .card-body {
    @apply p-6;
  }
}

@layer base {
  h1 { @apply text-4xl font-bold tracking-tight; }
  body { @apply antialiased text-gray-900; }
}

@layer utilities {
  .text-balance { text-wrap: balance; }
}
BS → TW: BS gives you .btn-primary out of the box. Tailwind makes you define it yourself via @apply. More work upfront, but you control everything — no "Bootstrap look" limitation.
