Introduction

What is TypeScript?

TypeScript is a strongly-typed superset of JavaScript created by Microsoft in 2012. It adds static type checking, interfaces, generics, and advanced type operators to JavaScript — all erased at compile time, producing plain JS that runs anywhere.

Type Safety

Catch errors at compile time instead of in production.

IntelliSense

Full autocompletion, go-to-definition, and inline docs.

Refactor Safely

Rename a property and see every broken reference instantly.

TypeScript vs JavaScript concept
ConcernJavaScriptTypeScript
Type checkingDynamic (runtime errors)Static (compile-time errors)
InterfacesNoneFull interface & type system
GenericsNoneFull generic programming
IDE supportBasicAutocomplete, refactoring, navigation
Error surfaceRuntimeCompile time
Learning curveLowModerate (types are optional)
OutputJSJS (types erased)
When to use TypeScript — any project that will be maintained by more than one person, any codebase larger than a handful of files, and any application where runtime type errors would be costly. For a throwaway script, plain JavaScript is fine.

Step 02 — Basics

Basic Types

Every value in TypeScript has a type. You can annotate variables explicitly or let TypeScript infer the type from the initial value.

Primitive Types typescript
// Explicit annotations
let name: string = "Alice";
let age: number = 30;
let active: boolean = true;
let nothing: null = null;
let notDefined: undefined = undefined;

// Type inference (no annotation needed)
let city = "Mumbai";      // inferred as string
let count = 42;            // inferred as number

// Arrays
let scores: number[] = [90, 85, 78];
let names: string[] = ["a", "b"];
let mixed: (string | number)[] = [1, "two", 3];

// Tuple
let pair: [string, number] = ["age", 25];
Special Types typescript
// any — disables type checking (avoid)
let risky: any = 42;
risky = "now a string";  // no error

// unknown — safe alternative to any
let input: unknown = "hello";
// input.toUpperCase();  // Error: must narrow first
if (typeof input === "string") {
  input.toUpperCase();    // OK after narrowing
}

// never — values that never occur
function throwError(msg: string): never {
  throw new Error(msg);
}

// void — function that returns nothing
function log(msg: string): void {
  console.log(msg);
}

// Object type
function printId(obj: object): void {
  console.log(obj);
}
Type Assertions typescript
// When you know more than TypeScript
let value: unknown = "hello";

// Angle-bracket syntax (not in .tsx files)
let len = (value as string).length;

// as syntax (preferred, works in .tsx)
let len2 = (value as string).length;
Prefer unknown over any. The unknown type forces you to check the value before using it, while any silently disables all type checking.
Step 03 — Shapes

Interfaces & Type Aliases

Both interface and type describe the shape of objects. Interfaces can be extended and merged; type aliases support unions, intersections, and mapped types.

Interfaces typescript
interface User {
  id: number;
  name: string;
  email: string;
  avatar?: string;  // optional
}

// Extending
interface Admin extends User {
  role: "admin" | "superadmin";
  permissions: string[];
}

// Merging (declaration merging)
interface User {
  createdAt: Date;
}
Type Aliases typescript
type Point = {
  x: number;
  y: number;
};

// Union
type Status = "active" | "inactive" | "banned";

// Intersection
type Timestamped = {
  createdAt: Date;
  updatedAt: Date;
};
type Post = User & Timestamped & {
  title: string;
  body: string;
};

// Literal type
type Direction = "up" | "down" | "left" | "right";

Step 04 — Functions

Functions

TypeScript adds types to function parameters and return values. The compiler can infer return types, but explicit annotations document intent and catch mistakes early.

Function Types typescript
// Explicit parameter and return types
function add(a: number, b: number): number {
  return a + b;
}

// Arrow function
const multiply = (a: number, b: number): number => a * b;

// Optional parameters (must be last)
function greet(name: string, greeting?: string): string {
  return `${greeting ?? "Hello"}, ${name}!`;
}

// Default parameters
function createUser(name: string, role = "user"): void {
  console.log(`Created ${role}: ${name}`);
}

// Rest parameters
function sum(...nums: number[]): number {
  return nums.reduce((a, b) => a + b, 0);
}

// Function type alias
type Callback = (data: string) => void;
function process(cb: Callback): void {
  cb("done");
}
Overloads typescript
// Function overloads — multiple call signatures
function format(value: string): string;
function format(value: number): string;
function format(value: string | number): string {
  if (typeof value === "string") return value.toUpperCase();
  return value.toFixed(2);
}

format("hello");  // OK
format(3.14);     // OK
// format(true);  // Error
TypeScript infers return types. For simple functions, you can omit the return type annotation and let the compiler infer it. Add explicit returns for public APIs and exported functions to document your contract.
Step 05 — Classes

Classes

TypeScript classes add access modifiers (public, private, protected), readonly, and abstract to JavaScript's class syntax.

Class Basics typescript
class Animal {
  public name: string;
  protected species: string;
  private id: number;
  readonly createdAt: Date;

  constructor(name: string, species: string, id: number) {
    this.name = name;
    this.species = species;
    this.id = id;
    this.createdAt = new Date();
  }

  public speak(): string {
    return `${this.name} makes a sound`;
  }
}

class Dog extends Animal {
  constructor(name: string, id: number) {
    super(name, "Canine", id);
  }

  public speak(): string {
    return `${this.name} barks`;
  }
}
Shorthand Constructor + Abstract Classes typescript
// Parameter property shorthand
class Point {
  constructor(
    public x: number,
    public y: number,
  ) {}
}

const p = new Point(10, 20);
console.log(p.x);  // 10

// Abstract class
abstract class Shape {
  abstract area(): number;
  abstract perimeter(): number;

  describe(): string {
    return `Area: ${this.area()}, Perimeter: ${this.perimeter()}`;
  }
}

class Circle extends Shape {
  constructor(public radius: number) { super(); }
  area(): number { return Math.PI * this.radius ** 2; }
  perimeter(): number { return 2 * Math.PI * this.radius; }
}
Step 06 — Generics

Generics

Generics let you write reusable code that works with any type while preserving type safety. They are the backbone of utility types, data structures, and library APIs.

Generic Functions & Interfaces typescript
// Generic function
function identity<T>(arg: T): T {
  return arg;
}

const str = identity<string>("hello");  // string
const num = identity(42);                // inferred as number

// Generic interface
interface ApiResponse<T> {
  data: T;
  status: number;
  message: string;
}

const res: ApiResponse<User> = {
  data: { id: 1, name: "Alice", email: "a@b.com" },
  status: 200,
  message: "OK",
};

// Generic with constraints
function getLength<T extends { length: number }>(arg: T): number {
  return arg.length;
}

getLength("hello");     // 5
getLength([1, 2, 3]);   // 3
// getLength(42);         // Error: number has no .length
Generic Classes & Defaults typescript
// Generic class
class Stack<T> {
  private items: T[] = [];

  push(item: T): void { this.items.push(item); }
  pop(): T | undefined { return this.items.pop(); }
  peek(): T | undefined { return this.items[this.items.length - 1]; }
  size(): number { return this.items.length; }
}

const nums = new Stack<number>();
nums.push(1);
nums.push(2);
// nums.push("3");  // Error

// Generic with default type
interface Paginated<T = unknown> {
  items: T[];
  total: number;
  page: number;
}

Practical Examples typescript
interface User {
  id: number;
  name: string;
  email: string;
  password: string;
}

// Update function — only pass changed fields
function updateUser(id: number, changes: Partial<Omit<User, "id">>) {
  // changes could have any subset of name, email, password
}

// Public user — no password
type PublicUser = Omit<User, "password">;

// Lookup table
type UserRoles = Record<string, "admin" | "editor" | "viewer">;
const roles: UserRoles = {
  alice: "admin",
  bob: "editor",
};

// Immutability
type FrozenUser = Readonly<User>;

Step 08 — Advanced

Advanced Types

Conditional types, mapped types, template literal types, and discriminated unions let you build precise, self-documenting type systems.

Discriminated Unions typescript
// A discriminated union uses a common literal property
type Result<T> =
  | { status: "ok"; data: T }
  | { status: "error"; message: string };

function handleResult<T>(result: Result<T>) {
  if (result.status === "ok") {
    console.log(result.data);    // TypeScript knows data exists
  } else {
    console.error(result.message); // TypeScript knows message exists
  }
}
Conditional Types typescript
// T extends U ? X : Y
type IsString<T> = T extends string ? true : false;

type A = IsString<"hello">;  // true
type B = IsString<42>;       // false

// infer keyword — extract types
type Unpack<T> = T extends Promise<infer U> ? U : T;
type Result = Unpack<Promise<string>>;  // string
Mapped Types & Template Literals typescript
// Mapped type — transform every property
type Optional<T> = {
  [K in keyof T]?: T[K];
};

// Template literal types
type EventName = "click" | "hover" | "focus";
type Handler = `on${Capitalize<EventName>}`;
// "onClick" | "onHover" | "onFocus"

// Type guards
function isString(val: unknown): val is string {
  return typeof val === "string";
}

const x: unknown = "hello";
if (isString(x)) {
  console.log(x.toUpperCase());  // OK
}

Step 10 — React

TypeScript + React

TypeScript is the standard for React projects. Every .tsx file gets full type checking for props, state, hooks, and events.

Component Props tsx
// Interface for props
interface ButtonProps {
  variant?: "primary" | "secondary" | "danger";
  size?: "sm" | "md" | "lg";
  disabled?: boolean;
  onClick?: () => void;
  children: React.ReactNode;
}

function Button({
  variant = "primary",
  size = "md",
  disabled = false,
  onClick,
  children,
}: ButtonProps) {
  return (
    <button
      className={`btn btn-${variant} btn-${size}`}
      disabled={disabled}
      onClick={onClick}
    >
      {children}
    </button>
  );
}
Hooks & Events tsx
import { useState, useRef, useEffect } from "react";

// useState with types
const [count, setCount] = useState<number>(0);
const [user, setUser] = useState<User | null>(null);

// useRef with types
const inputRef = useRef<HTMLInputElement>(null);
const timerRef = useRef<ReturnType<typeof setTimeout> | null>(null);

// Event handlers
function handleChange(e: React.ChangeEvent<HTMLInputElement>) {
  setValue(e.target.value);
}

function handleSubmit(e: React.FormEvent<HTMLFormElement>) {
  e.preventDefault();
}

// Generic component
function List<T extends { id: string }>({
  items,
  renderItem,
}: {
  items: T[];
  renderItem: (item: T) => React.ReactNode;
}) {
  return <ul>{items.map(item => <li key={item.id}>{renderItem(item)}</li>)}</ul>;
}
Context with Types tsx
interface AuthContextType {
  user: User | null;
  login: (email: string, password: string) => Promise<void>;
  logout: () => void;
}

const AuthContext = React.createContext<AuthContextType | null>(null);

function useAuth(): AuthContextType {
  const ctx = React.useContext(AuthContext);
  if (!ctx) throw new Error("useAuth must be inside AuthProvider");
  return ctx;
}
Step 11 — Practices

Best Practices

Enable strict: true from day one. It catches the most common mistakes and forces you to write explicit, intentional code.
Do
  • Use unknown instead of any
  • Enable strict: true in tsconfig
  • Use type inference when the type is obvious
  • Prefer interfaces for object shapes
  • Use discriminated unions for state machines
  • Use as const for literal values
  • Use generic constraints (extends)
  • Use @types/ packages for libraries
Don't
  • Don't use any as a quick escape
  • Don't annotate when inference is clear
  • Don't use @ts-ignore without a comment
  • Don't over-abstract with too many generics
  • Don't mix interface and type inconsistently
  • Don't use enums (prefer as const objects)
  • Don't use Object, String, Number wrapper types
  • Don't ignore the compiler — fix the error
