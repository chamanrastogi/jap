What is Node.js?

Node.js is a JavaScript runtime built on Chrome's V8 engine. Where PHP runs inside a web server (Apache/nginx/FPM), Node runs its own process and speaks HTTP itself. The same language that runs in the browser runs your backend — one language, two sides of the wire.

For Laravel/PHP developers: the mental model is closer to PHP-FPM + a framework than to front-end JS. You write app.listen(3000), Express routes replace routes/web.php, middleware replaces your $middleware stack, and res.json() replaces response()->json().

The Event Loop (why you must never block)

Node runs one thread for your JavaScript. Slow code on that thread pauses every request. Heavy work (files, DB, network) is handed off to the OS and resumed via the callback queue — that's why async/await is not optional, it's the whole model. 

// BLOCKING â€” sleeps the whole server (avoid)
import { execSync } from 'node:child_process';
const output = execSync('grep -r secret /var/log'); // blocks every request

// NON-BLOCKING â€” async/await yields back to the event loop
import { exec } from 'node:child_process';
const getLogs = async () => await exec('grep -r secret /var/log');

Express Basics

Express is a tiny, unopinionated web framework. It gives you routing, middleware, and req/res helpers — nothing else. You compose the rest.

The Express 5 "shapes" you must know
import express from 'express';
const app = express();

app.use(express.json());                     // middleware: parse JSON bodies
app.use(express.urlencoded({ extended: true })); // form bodies

app.METHOD(path, handler);                  // route:  GET/POST/PUT/PATCH/DELETE
app.use(path, middleware);                  // middleware: runs for matching path

// handler signature â€” 3 args (middleware can also take next)
app.get('/users', (req, res) => {
  res.json({ ok: true, users: [] });
});

// Async handlers: Express 5 catches rejected promises automatically
app.get('/users/:id', async (req, res) => {
  const user = await db.findUser(req.params.id);
  if (!user) return res.status(404).json({ error: 'Not found' });
  res.json(user);
});
req (request) â€” common props
req.params     // /users/:id â†’ { id: '5' }
req.query      // ?page=2 â†’ { page: '2' }
req.body       // parsed JSON/form body (needs middleware)
req.headers    // request headers object
req.cookies    // needs cookie-parser
req.get('x-api-key') // read a header
req.path, req.method, req.ip
res (response) â€” common methods
res.json(obj)       // send JSON (sets Content-Type)
res.status(code)    // set HTTP status, chainable
res.send(str)       // plain text/HTML
res.sendStatus(204) // status only, no body
res.set('x-api', '1') // custom header
res.redirect('/')   // 302 redirect
res.end()           // end response

The Middleware Pipeline

Middleware is a function that runs between receiving a request and sending a response. Every request travels down a stack of functions; each one can respond, or call next() to pass control to the next. Order matters — it's the single most important Express concept.

Anatomy of a middleware function
const logger = (req, res, next) => {
  console.log(`${req.method} ${req.originalUrl}`);
  next();            // â† pass to the next function in the stack
};

const requireAuth = (req, res, next) => {
  if (!req.headers.authorization) {
    return res.status(401).json({ error: 'Missing token' });
  }
  next();
};

app.use(logger);                    // runs for EVERY request
app.use('/api', requireAuth);      // runs only for /api/* routes

Boilerplate server (the order you should copy)
import express from 'express';
import morgan from 'morgan';
import cors from 'cors';
import helmet from 'helmet';
import userRouter from './routes/users.js';

const app = express();

app.use(helmet());                    // 1. security headers
app.use(cors());                      // 2. CORS
app.use(express.json());              // 3. parse JSON bodies
app.use(morgan('dev'));             // 4. logging

app.use('/api/users', userRouter);  // 5. your routes

// 404 + error handler MUST be last
app.use((req, res) => res.status(404).json({ error: 'Not found' }));
app.use((err, req, res, next) => {
  console.error(err);
  res.status(err.status ?? 500).json({ error: err.message });
});

app.listen(process.env.PORT ?? 3000);

Routing

Routes map an HTTP method + path to a handler. Use an express.Router() per resource and mount it on the app — the routing version of splitting Laravel routes into separate files.

routes/users.js â€” the Router pattern
import { Router } from 'express';

const router = Router();

router.param('id', async (req, res, next, id) => {
  req.user = await db.findUser(id);
  if (!req.user) return res.status(404).json({ error: 'User not found' });
  next();
});

router.get('/', async (req, res) => res.json(users));      // GET    /api/users
router.get('/:id', (req, res) => res.json(req.user));         // GET    /api/users/7
router.put('/:id', (req, res) => { ... });                    // PUT    /api/users/7
router.delete('/:id', (req, res) => { ... });                 // DELETE /api/users/7

export default router;
Route path patterns
PatternMatches
/users/:id/users/5 â†’ req.params.id = "5"
/users/:id/edit/users/5/edit (static segments mix)
/files/*/files/anything/here (wildcard, Express 5 uses /*)
app.all('/x', h)Any HTTP method on /x

Express 5 note: the old string wildcard * was replaced — use named wildcards like /files/*splat or a regex. Regex patterns still work: /^\/api\/v\d+/.

REST API Design

REST is a set of conventions, not a standard. Stay consistent and your API becomes predictable. The rules below are the ones that survive in production.

Resource naming & HTTP verbs
RouteMeaning
GET/api/usersList users (collection)
GET/api/users/:idFetch one user
POST/api/usersCreate a user (body = new record)
PUT/api/users/:idReplace a user (full resource)
PATCH/api/users/:idPartially update a user
DELETE/api/users/:idDelete a user
Good practice
  • Plural nouns: /users, not /user
  • Version the API: /api/v1/users
  • Nested only for true ownership: /users/:id/posts
  • Use query params for filters/pagination, not verbs
  • Use the correct status codes (table below)
Avoid
  • Verbs in URLs: /getUser, /createUser
  • GET with a body (most clients can't send one)
  • Returning 200 for everything — even failures
  • Storing passwords in plain text
  • Exposing stack traces in error responses
Status codes cheat
CodeMeaningWhen
200OKGET, PUT, PATCH success
201CreatedPOST success — include Location header
204No ContentDELETE success, empty body
400Bad RequestInvalid body / missing field
401UnauthorizedMissing / invalid credentials
403ForbiddenAuthenticated but not allowed
404Not FoundResource / route doesn't exist
409ConflictDuplicate, state conflict (e.g. unique email)
422UnprocessableValidation rules failed
429Too Many RequestsRate limited
500Server ErrorUnexpected exception

Full CRUD Example

A complete, runnable in-memory CRUD API. The patterns here — route params, body parsing, status codes, 404s — are exactly what you'll reproduce against a real database.

src/index.js â€” complete app
import express from 'express';
import { randomUUID } from 'node:crypto';

const app = express();
app.use(express.json());

// in-memory store (swap for MySQL later)
const users = [
  { id: 'a1', name: 'Ada', role: 'admin' },
  { id: 'b2', name: 'Linus', role: 'dev' },
];

// LIST
app.get('/api/users', (req, res) => res.json(users));

// CREATE
app.post('/api/users', (req, res) => {
  const { name, role } = req.body;
  if (!name) return res.status(400).json({ error: 'name is required' });
  const user = { id: randomUUID(), name, role: role ?? 'dev' };
  users.push(user);
  res.status(201).json(user);
});

// READ ONE
app.get('/api/users/:id', (req, res) => {
  const user = users.find(u => u.id === req.params.id);
  if (!user) return res.status(404).json({ error: 'User not found' });
  res.json(user);
});

// UPDATE
app.patch('/api/users/:id', (req, res) => {
  const user = users.find(u => u.id === req.params.id);
  if (!user) return res.status(404).json({ error: 'User not found' });
  Object.assign(user, req.body);
  res.json(user);
});

// DELETE
app.delete('/api/users/:id', (req, res) => {
  const idx = users.findIndex(u => u.id === req.params.id);
  if (idx === -1) return res.status(404).json({ error: 'User not found' });
  users.splice(idx, 1);
  res.sendStatus(204);
});

app.listen(3000, () => console.log('API on :3000'));

Validation

Never trust req.body. Validate input before it touches your database. zod is the modern default — schema + type inference in one.

zod schema + async handler
npm install zod

import { z } from 'zod';

const CreateUser = z.object({
  name: z.string().min(2).max(80),
  email: z.string().email(),
  age: z.coerce.number().int().min(18).optional(),
  role: z.enum(['admin', 'dev', 'viewer']).default('dev'),
});

app.post('/api/users', (req, res) => {
  const parsed = CreateUser.safeParse(req.body);

  if (!parsed.success) {
    return res.status(422).json({
      error: 'Validation failed',
      issues: parsed.error.flatten().fieldErrors,
    });
  }
  const user = createUser(parsed.data);   // parsed.data is fully typed
  res.status(201).json(user);
});
422 vs 400: use 400 for malformed JSON or wrong types, and 422 when the request is well-formed but fails your business rules.

Error Handling

Error middleware has 4 arguments — Express identifies it by that signature. It must be registered last, after all routes.

Centralized error handler
// errors.js â€” a small helper
export class HttpError extends Error {
  constructor(status, message) {
    super(message);
    this.status = status;
  }
}

// throw anywhere, Express 5 routes async errors here automatically
import { HttpError } from './errors.js';

app.get('/api/users/:id', async (req, res) => {
  const user = await db.findUser(req.params.id);
  if (!user) throw new HttpError(404, 'User not found');
  res.json(user);
});

// last middleware â€” the one true error handler
app.use((err, req, res, next) => {
  console.error('ERR', err);                 // always log full error server-side
  res.status(err.status ?? 500).json({
    error: err.status ? err.message : 'Internal server error',
  });
});
Never leak internals. Only send err.message when you set err.status yourself. For unexpected errors, reply with a generic message and keep the real stack trace in the server logs.

Database (MySQL)

Two common paths: the mysql2 driver with execute() prepared statements (like PDO), or an ORM/query builder like Prisma, Drizzle, or Knex. For a PHP developer, mysql2 prepared statements feel the most familiar.

mysql2 pool + prepared statements
npm install mysql2 dotenv

// db.js
import mysql from 'mysql2/promise';

export const pool = mysql.createPool({
  host: process.env.DB_HOST,
  user: process.env.DB_USER,
  password: process.env.DB_PASS,
  database: process.env.DB_NAME,
  waitForConnections: true,
  connectionLimit: 10,
});

// route â€” async/await, prepared statements
app.get('/api/users', async (req, res) => {
  const [rows] = await pool.execute(
    'SELECT id, name, email FROM users WHERE active = ? ORDER BY id DESC LIMIT ?',
    [1, 50]
  );
  res.json(rows);
});

// .env (never commit this file)
// DB_HOST=localhost
// DB_USER=root
// DB_PASS=secret
// DB_NAME=myapp

Auth & JWT

The standard stateless API flow: bcryptjs to hash passwords, jsonwebtoken to sign tokens, a middleware to verify them.

Login â†’ token â†’ protected route
npm install bcryptjs jsonwebtoken

import bcrypt from 'bcryptjs';
import jwt from 'jsonwebtoken';

// register â€” hash the password, NEVER store plain text
const hash = await bcrypt.hash(req.body.password, 10);

// login â€” compare, then sign
const ok = await bcrypt.compare(req.body.password, user.password_hash);
if (!ok) return res.status(401).json({ error: 'Invalid credentials' });

const token = jwt.sign(
  { sub: user.id, role: user.role },
  process.env.JWT_SECRET,
  { expiresIn: '1d' }
);
res.json({ token });

// protect middleware â€” verify on every request
const auth = (req, res, next) => {
  const [ , token ] = req.headers.authorization?.split(' ') ?? [];
  try {
    req.user = jwt.verify(token, process.env.JWT_SECRET);
    next();
  } catch {
    res.status(401).json({ error: 'Invalid or expired token' });
  }
};

app.get('/api/me', auth, (req, res) => res.json(req.user));
Security floor: put JWT_SECRET in .env, never in code. Prefer short-lived tokens + refresh tokens for real apps. Add express-rate-limit on login to slow brute-force attempts.

Testing

Node ships a built-in test runner (node:test). Pair it with supertest to hit your Express app without opening a port.

API tests with node:test + supertest
npm install --save-dev supertest

// index.test.js  â†’  npm test runs it
import { test, describe } from 'node:test';
import assert from 'node:assert/strict';
import request from 'supertest';
import app from './index.js';

describe('POST /api/users', () => {
  test('creates a user', async () => {
    const res = await request(app)
      .post('/api/users')
      .send({ name: 'Grace' });
    assert.equal(res.status, 201);
    assert.ok(res.body.id);
  });

  test('rejects missing name', async () => {
    const res = await request(app).post('/api/users').send({});
    assert.equal(res.status, 400);
  });
});
Export the app separately from the app.listen() call so tests can import it without binding a port: export default app in one file, listen in server.js.
