htmx

Complete Reference & Concept Guide v2.x HTML-over-Wire Hypermedia-Driven

htmx gives you access to AJAX, CSS Transitions, WebSockets and Server-Sent Events directly in HTML, using attributes like hx-get, hx-post, and hx-target. No JavaScript required for most interactions.

What is htmx?

htmx is a library that allows you to build modern web UIs with HTML alone. It extends HTML with custom attributes that let you:

Make Requests
GET, POST, PUT, PATCH, DELETE from any element
Swap Content
Replace parts of the DOM with server responses
Animate
Use CSS transitions during swaps
Key Philosophy
  • Hypermedia-Driven — the server returns HTML, not JSON
  • Progressively Enhanced — works with or without JavaScript
  • Backend-Agnostic — works with any language or framework
  • Replace jQuery/AJAX — no client-side rendering needed

Request Attributes

These attributes define what HTTP request to make and where to send it.

AttributeDescription
hx-getSend a GET request to the specified URL
hx-postSend a POST request (form data or JSON)
hx-putSend a PUT request
hx-patchSend a PATCH request
hx-deleteSend a DELETE request
hx-requestAdvanced request config (timeout, credentials, etc.)
hx-headersAdd custom headers to the request
hx-valsInclude additional JSON values in the request
hx-paramsFilter which params are submitted (form)
hx-includeInclude values from other elements in the request
Basic Example
<!-- Click button -> GET /time -> swap response into #result -->
<button hx-get="/time" hx-target="#result">
  Get Current Time
</button>
<div id="result"></div>

<!-- Form submission via POST -->
<form hx-post="/contact" hx-target="#response">
  <input type="text" name="email">
  <button type="submit">Submit</button>
</form>
<div id="response"></div>

Targeting & Swapping

Control where the response goes and how it replaces content.

AttributeDescription
hx-targetCSS selector for the element to swap content into
hx-swapHow to swap the response (innerHTML, outerHTML, etc.)
hx-selectSelect a subset of the response to swap
hx-select-oobOut-of-band swap â€” update multiple elements
hx-preservePreserve element content across swaps
hx-swap-oobMark element as out-of-band in the response
Target Examples
<!-- Target by ID -->
<button hx-get="/data" hx-target="#my-div">Load</button>

<!-- Target closest parent matching a class -->
<button hx-get="/edit" hx-target="closest .card">Edit</button>

<!-- Target next sibling -->
<button hx-get="/details" hx-target="next .details">Show</button>

<!-- Target this element -->
<button hx-get="/replace-me" hx-target="this">Replace Me</button>

<!-- Select part of the response (discard rest) -->
<button hx-get="/page" hx-select="#main-content">Load Content</button>

Triggers

hx-trigger controls when the request is sent. Default trigger depends on the element (click for buttons, change for inputs).

TriggerDescription
clickFires on click (default for <button>, <a>)
changeFires on value change (default for <input>, <select>)
keyupFires on keyup (use with delay for search-as-you-type)
loadFires when element is loaded (for lazy loading)
revealedFires when element scrolls into view (lazy loading)
everyFires on an interval (e.g., every 5s)
intersectFires when element intersects viewport
click throttle:500msThrottle to one request per 500ms
keyup delay:300msDebounce with delay
click onceFires only once
Trigger Examples
<!-- Search as you type (debounced 300ms) -->
<input type="search" name="q"
       hx-get="/search" hx-trigger="keyup delay:300ms"
       hx-target="#results">

<!-- Lazy load on page load -->
<div hx-get="/slow-content" hx-trigger="load">
  Loading...
</div>

<!-- Lazy load when scrolled into view -->
<div hx-get="/images" hx-trigger="revealed">
  Scroll to load
</div>

<!-- Poll every 5 seconds -->
<div hx-get="/notifications" hx-trigger="every 5s"
     hx-swap="innerHTML">
  No new notifications
</div>

<!-- Click with throttle -->
<button hx-post="/save" hx-trigger="click throttle:2s">
  Save (throttled)
</button>

hx-boost & SPA-like Navigation

hx-boost converts normal <a> tags and <form> elements into AJAX requests, giving you a SPA-like experience without any JS.

<!-- Boost all links on the page -->
<body hx-boost="true">
  <a href="/about">About</a>  <!-- becomes AJAX request -->
  <a href="/contact">Contact</a> <!-- becomes AJAX request -->
</body>

<!-- Exclude specific links from boosting -->
<a href="/download.pdf" hx-boost="false">Download PDF</a>
▶ hx-push-url — Push the request URL into browser history so the back button works: hx-push-url="true"

Swap Strategies

The hx-swap attribute controls how the response replaces the target element.

StrategyDescription
innerHTMLReplace child content (default)
outerHTMLReplace the entire target element
beforebeginInsert before the target element
afterbeginInsert as first child of target
beforeendInsert as last child of target
afterendInsert after the target element
deleteDelete the target element (ignores response)
noneDon't swap (use with events only)
Swap Modifiers
<!-- Settle delay before swap takes effect -->
<button hx-get="/data" hx-swap="innerHTML swap:300ms">Swap</button>

<!-- Settle delay for CSS transitions -->
<button hx-get="/data" hx-swap="innerHTML settle:500ms">Settle</button>

<!-- Combine modifiers -->
<button hx-get="/data" hx-swap="outerHTML swap:200ms settle:400ms">
  Custom Timing
</button>
Out-of-Band Swaps

Update multiple elements on the page with a single response using hx-swap-oob on the response HTML.

<!-- Server response can update multiple targets -->
<!-- This HTML is returned by the server -->
<div id="main-content">
  New main content here
</div>
<div id="sidebar" hx-swap-oob="true">
  Updated sidebar
</div>
<div id="notification-count" hx-swap-oob="innerHTML">
  3
</div>

CSS Transitions

htmx works with the View Transitions API for smooth animations during swaps.

<!-- Enable view transitions on swap -->
<button hx-get="/new-content" hx-swap="innerHTML transition:true">
  Animate
</button>

<!-- CSS for the transition -->
<style>
  @keyframes fade-in {
    from { opacity: 0; }
    to   { opacity: 1; }
  }
  @keyframes fade-out {
    from { opacity: 1; }
    to   { opacity: 0; }
  }
  ::view-transition-old(root) {
    animation: fade-out 0.3s ease;
  }
  ::view-transition-new(root) {
    animation: fade-in 0.3s ease;
  }
</style>

PHP Integration

htmx works naturally with PHP â€” the server returns HTML fragments, not JSON.

Basic PHP Handler
<!-- HTML (htmx) -->
<button hx-get="/time.php" hx-target="#time">
  Get Current Time
</button>
<div id="time"></div>
<!-- time.php (returns HTML fragment) -->
<p><?= date('Y-m-d H:i:s') ?></p>
Form Processing
<!-- HTML -->
<form hx-post="/contact.php" hx-target="#feedback">
  <input type="email" name="email" required>
  <button type="submit">Subscribe</button>
</form>
<div id="feedback"></div>
<!-- contact.php -->
<?php
$email = filter_input(INPUT_POST, 'email', FILTER_VALIDATE_EMAIL);

if (!$email) { ?>
  <div class="alert alert-danger">Invalid email address.</div>
<?php return; } ?>

<!-- Success response (replaces form with success message) -->
<div class="alert alert-success">
  Thanks! Check your inbox.
</div>
Updating Multiple Regions (OOB)
<!-- save.php -- returns HTML with OOB swaps -->
<?php
$id = filter_input(INPUT_POST, 'id', FILTER_VALIDATE_INT);
save_to_db($id);
?>

<!-- Main target (the row being edited) -->
<tr id="row-<?= $id ?>">
  <td>Saved!</td>
</tr>

<!-- Out-of-band: update counter in sidebar -->
<span id="counter" hx-swap-oob="true">
  <?= get_count() ?>
</span>

<!-- Out-of-band: show flash message -->
<div id="flash" hx-swap-oob="true">
  Record updated successfully!
</div>
▶ Key insight: PHP is a natural fit for htmx. You don't need a JSON API â€” just write HTML fragments as responses. Set headers like HX-Trigger from PHP using header('HX-Trigger: {"myEvent": "data"}').

Laravel Integration

<!-- Blade template with htmx -->
<button
  hx-get="{{ route('posts.index') }}"
  hx-target="#post-list"
  hx-push-url="true"
  class="btn btn-primary"
>
  Load Posts
</button>
<div id="post-list">
  @include('partials.post-list')
</div>
// Controller â€” check for htmx request
use Illuminate\Http\Request;

class PostController extends Controller
{
    public function index(Request $request)
    {
        $posts = Post::latest()->paginate(10);

        // If htmx request, only return the partial
        if ($request->header('HX-Request')) {
            return view('partials.post-list', compact('posts'));
        }

        // Full page load
        return view('posts.index', compact('posts'));
    }
}

JSON & API Responses

While htmx prefers HTML responses, it can work with JSON by using the json-enc extension and hx-swap with client-side-templates extension.

<!-- Submit form data as JSON -->
<form hx-post="/api/users"
      hx-ext="json-enc"
      hx-target="#result">
  <input name="name" placeholder="Name">
  <input name="email" placeholder="Email">
  <button>Create</button>
</form>

<!-- Client-side template extension (mustache, etc.) -->
<div hx-ext="client-side-templates">
  <button hx-get="/api/users"
          hx-target="#user-table"
          hx-swap="innerHTML"
          mustache-template="user-row">
    Load Users
  </button>
  <template id="user-row">
    {{#users}}
      <tr>
        <td>{{name}}</td>
        <td>{{email}}</td>
      </tr>
    {{/users}}
  </template>
  <table id="user-table"></table>
</div>

Events & Hooks

EventDescription
htmx:beforeRequestFired before a request is made
htmx:afterRequestFired after a request completes
htmx:beforeSwapFired before content is swapped
htmx:afterSwapFired after content is swapped
htmx:beforeOnLoadFired before response is processed
htmx:configRequestModify request parameters
htmx:responseErrorFired on HTTP error responses
htmx:sendErrorFired on network error
Listening to Events
// Client-side JavaScript
document.addEventListener('htmx:afterRequest', function(evt) {
    console.log('Status:', evt.detail.xhr.status);
    console.log('Target:', evt.detail.target);
});

// Modify request parameters before sending
document.addEventListener('htmx:configRequest', function(evt) {
    evt.detail.headers['X-CSRF-Token'] = 'my-token';
    evt.detail.parameters['_token'] = 'csrf-value';
});

// HX-Trigger from server â€” listen for custom events
document.addEventListener('post-created', function(evt) {
    showToast('Post #' + evt.detail.id + ' created!');
});
Triggering Events from the Server
<!-- PHP -->
// Single event
header('HX-Trigger: post-created');

// With data
header('HX-Trigger: {"post-created":{"id":42}}');

// Laravel
return response()
    ->view('partials.post-row', compact('post'))
    ->header('HX-Trigger', json(['post-created' => ['id' => $post->id]]));

Common Patterns

Infinite Scroll

     hx-target="this"

Best Practices

Architecture
  • Return HTML fragments, not JSON (let server handle rendering)
  • Use partial templates for each interactive region
  • Check HX-Request header to return partial vs full page
  • Use hx-boost for SPA-like navigation with minimal effort
  • Keep htmx version pinned (avoid breaking changes)
Security
  • Always validate and sanitize server-side (CSRF with hx-headers)
  • Use hx-confirm for destructive actions
  • Don't trust HX-* headers (they're client-controlled)
  • Escape output in HTML fragments (same as any HTML)
  • Use Content Security Policy headers
Performance
  • Use hx-trigger with delay or throttle to reduce requests
  • Lazy-load below-the-fold content with revealed trigger
  • Return minimal HTML (only the fragment needed)
  • Cache server responses where possible
  • Keep swap targets specific (avoid swapping large sections)
Developer Experience
  • Use browser dev tools — network tab shows HX-* headers
  • Install the htmx DevTools extension
  • Start simple: one hx-get + hx-target at a time
  • Combine htmx with Alpine.js for complex client-side state
  • Read the official docs for edge cases
