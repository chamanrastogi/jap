What is React Native?

React Native runs React components on the phone. There is no web browser and no DOM — your JavaScript talks to native UI through the framework, so a <Text> becomes a real UILabel on iOS or TextView on Android. You write once, ship to iOS, Android, and (with React Native Web) the browser.

Rule of thumb for 2026: start with create-expo-app. You can always npx expo prebuild later to get the native projects. Bare CLI is for teams that know they need deep native changes from day one.

Setup with Expo

Requirements: Node.js 22.13+, a phone with the Expo Go app (or an emulator), and optionally Xcode / Android Studio.

# Create an app (SDK 57 → React Native 0.86, React 19.2)
npx create-expo-app@latest myapp

# Start the dev server → scan the QR code with Expo Go
cd myapp
npx expo start

# Start for a specific platform
npx expo start --ios      # iOS simulator
npx expo start --android  # Android emulator
npx expo start --web      # browser via react-native-web

# Check your project is healthy
npx expo-doctor
Everyday Expo CLI commands
CommandWhat it does
npx expo startStart Metro dev server + QR code
npx expo install pkgInstall a package pinned to the SDK version
npx expo prebuildGenerate ios/ and android/ native projects
npx expo run:iosBuild + run on a simulator (needs Xcode)
npx expo run:androidBuild + run on an emulator (needs Android Studio)
npx expo exportBundle the app for production / EAS Update
npx expo-doctorAudit dependencies, versions, and config
npx expo install expo@latest --fixUpgrade to the newest SDK
Expo Go vs a development build. Expo Go runs JS-only apps instantly — perfect for learning. When you add a library with native code, switch to a development build: npx expo run:ios / npx expo run:android.

Project Structure

SDK 57 apps are file-based: routes live in app/ (Expo Router), everything else is organized the way you like.

myapp/
  app/                # screens become routes (Expo Router)
    _layout.tsx       # root layout
    index.tsx         # route "/"
    about.tsx         # route "/about"
    profile/[id].tsx  # dynamic route "/profile/:id"
  components/         # reusable UI (Button, Card, …)
  constants/          # colors, theme tokens
  assets/             # images, fonts, icons
  app.json            # app config (name, icon, splash)
  package.json
  tsconfig.json
app.json essentials
{ // app.json — the single source of app identity
  "expo": {
    "name": "MyApp",
    "slug": "myapp",
    "version": "1.0.0",
    "orientation": "portrait",
    "icon": "./assets/icon.png",
    "splash": { "image": "./assets/splash.png" },
    "ios": { "bundleIdentifier": "com.you.myapp" },
    "android": { "package": "com.you.myapp" }
  }
}

Core Components

A small set of components replaces the whole HTML tag library. No <div>, no <p> — just these building blocks.

View
≈ div
Layout container. The workhorse of every screen.
Text
≈ p / span
Every string on screen must live inside Text.
ScrollView
≈ body scroll
Scrollable container for small content sets.
FlatList
≈ virtualized list
Efficient long lists — only renders visible rows.
Pressable
≈ button / a
Touchable element with pressed/disabled styles.
TextInput
≈ input
Text entry with keyboard handling.
Image
≈ img
Remote or bundled images.
SafeAreaView
—
Pad past the notch / status bar. (deprecated in RN 0.86 — use react-native-safe-area-context).
A first screen
import { View, Text, StyleSheet, Pressable } from 'react-native';

export default function Home() {
  return (
    <View style={styles.container}>
      <Text style={styles.title}>Namaste, world!</Text>
      <Pressable
        style={({ pressed }) => [styles.btn, pressed && styles.btnPressed]}
        onPress={() => console.log('tapped')}
      >
        <Text style={styles.btnText}>Tap me</Text>
      </Pressable>
    </View>
  );
}

const styles = StyleSheet.create({
  container: { flex: 1, alignItems: 'center', justifyContent: 'center' },
  title: { fontSize: 24, fontWeight: '700' },
  btn: { backgroundColor: '#6a5af9', padding: 12 24, borderRadius: 12 },
  btnPressed: { opacity: 0.75 },
  btnText: { color: '#fff', fontWeight: '600' },
});
FlatList — virtualized long lists
import { FlatList, Text, View } from 'react-native';

const data = Array.from({ length: 1000 }, (_, i) => ({ id: i, name: `Item ${i}` }));

export default function List() {
  return (
    <FlatList
      data={data}
      keyExtractor={(item) => item.id}
      renderItem={({ item }) => (
        <View style={{ padding: 12 }}>
          <Text>{item.name}</Text>
        </View>
      )}
    />
  );
}

Styling with StyleSheet

Styling is inline object literal CSS — camelCase property names, no selectors, no cascade, no px units (numbers are density-independent pixels). Flexbox is the only layout engine. 

const styles = StyleSheet.create({
  card: {
    flexDirection: 'row',         // flexbox is default — like display:flex
    alignItems: 'center',
    justifyContent: 'space-between',
    gap: 8,                      // gap works, like CSS gap
    padding: 16,
    backgroundColor: '#fff',
    borderRadius: 12,
    shadowColor: '#000',          // iOS shadow
    shadowOpacity: 0.1,
    shadowRadius: 8,
    elevation: 3,               // Android shadow
  },
  title: { fontSize: 16, fontWeight: '600', color: '#14182b' },
});

// Merge styles: array wins last → great for pressed / selected states
<View style={[styles.card, isSelected && styles.cardSelected]} />

// Platform-specific values inside one style
fontFamily: Platform.select({ ios: 'Helvetica Neue', android: 'sans-serif' })

Layout & Responsive

Responsive with useWindowDimensions
import { useWindowDimensions, View } from 'react-native';

export default function Gallery() {
  const { width } = useWindowDimensions();      // updates on rotate / resize
  const columns = width > 600 ? 4 : 2;

  return (
    <View style={{ flexDirection: 'row', flexWrap: 'wrap' }}>
      {items.map(item => (
        <View key={item.id} style={{ width: 100 / columns + '%', padding: 4 }} />
      ))}
    </View>
  );
}

Navigation

Expo Router is the file-based router (the mobile version of Next.js App Router). Screens become routes inside app/, and it works with typed routes. 

// app/_layout.tsx — root layout
import { Stack } from 'expo-router';

export default function RootLayout() {
  return <Stack />;
}

// app/index.tsx — screen at "/"
import { router } from 'expo-router';
<Pressable onPress={() => router.push('/profile/42')}>...</Pressable>;

// app/profile/[id].tsx — dynamic route, typed
import { useLocalSearchParams } from 'expo-router';

export default function Profile() {
  const { id } = useLocalSearchParams();
  return <Text>Profile {id}</Text>;
}
Alternative: React Navigation still works and remains popular for tab/drawer/stack setups. In SDK 57, Expo Router is the default template — it is built on React Navigation under the hood, so you get both worlds.

Platform-Specific Code

One codebase, but sometimes a screen really is different on each platform.

// 1. The Platform module — branch inline
import { Platform, StyleSheet } from 'react-native';

const isIos = Platform.OS === 'ios';      // 'ios' | 'android' | 'web' | 'windows' | 'macos'

const styles = StyleSheet.create({
  btn: {
    padding: Platform.select({ ios: 14, android: 10, default: 12 }),
  },
});

// 2. Platform-specific files — rename with .ios. / .android.
//   Card.ios.tsx    → compiles on iOS only
//   Card.android.tsx → compiles on Android only
//   Card.tsx         → fallback / web
import Card from './Card';  // resolves per-platform automatically

Networking & Data

// fetch works exactly like the web (uses NSURLSession / OkHttp underneath)
const loadUsers = async () => {
  const res = await fetch('https://api.example.com/users');
  if (!res.ok) throw new Error('Request failed');
  return res.json();
};

// Load once with useEffect — then render states
const [users, setUsers] = useState([]);
const [loading, setLoading] = useState(true);

useEffect(() => {
  loadUsers()
    .then(setUsers)
    .finally(() => setLoading(false));
}, []);

State Management

Same rules as React: start with useState + Context, add a store when it grows.

// Zustand — the lightweight store most RN teams use
import { create } from 'zustand';

const useCart = create((set) => ({
  items: [],
  add: (item) => set((s) => ({ items: [...s.items, item] })),
  clear: () => set({ items: [] }),
}));

function CartBadge() {
  const count = useCart((s) => s.items.length);
  return <Text>{count} items</Text>;
}
Persistence tip: add zustand/middleware persist with AsyncStorage to keep the store across app restarts.

The New Architecture

React Native 0.82+ (October 2025) runs entirely on the New Architecture — there is no going back. For you this mostly means: faster, less JS bridge, and synchronous native calls.

Old vs New — what actually changed
Legacy (frozen Jun 2025)New Architecture
UI layerUI Manager, asyncFabric — synchronous rendering
Native modulesBridge, JSON serializationTurboModules — direct JSI calls
JS ↔ nativeAsync JSON bridgeJSI — zero-copy, sync, shared memory
Startup modeBridged runtimeBridgeless by default
EngineHermes V0 (default)Hermes V1 (default since 0.84)
 
// What "bridge vs JSI" means in practice: native calls are now direct.
// Legacy:  JS → JSON → Bridge → native → JSON → JS   (async, every call)
// New:     JS → JSI → native function                  (sync, no copy)

// Native modules via Expo Modules API work on the New Architecture by default:
npx create-expo-module@latest --local
Practical takeaway: if you use SDK 55+ you are on the New Architecture, period. Libraries written with the Expo Modules API work automatically — prefer those when choosing packages.

Build & Deploy

EAS Build — the cloud build service
npm install -g eas-cli
eas login
eas build --profile production --platform ios    # or android, or all
eas submit -p ios --latest                        # ship to App Store Connect
eas submit -p android --latest                    # ship to Play Console

# Over-the-air JS updates (no store review)
eas update --channel production
App Store (iOS)
  • Apple Developer account ($99/yr)
  • App icon + splash screens required
  • Privacy labels (App Privacy section)
  • Review takes ~1–3 days
Play Store (Android)
  • Play Console account ($25 one-time)
  • AAB bundle (EAS produces it)
  • Content rating + data safety forms
  • Review is usually fast (hours–2 days)
Version discipline: bump app.json → version and the native build number (buildNumber / versionCode) on every release. Stores reject a build that repeats an existing version number.
