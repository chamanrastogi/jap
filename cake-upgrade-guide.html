CakePHP Upgrade Guide

Comprehensive path for upgrading CakePHP 2.x → 3.x → 4.x → 5.x

4

15+

5
PHP Majors
Never skip versions. Always upgrade incrementally (2→3→4→5). Direct jumps cause dependency conflicts and missing migration paths.

Upgrade Checklist

Before You Start
Backup database + full codebase (git tag + SQL dump)
Verify current PHP version meets next target
Audit custom finders, behaviors, components for deprecated calls
List all third-party plugins and check their upgrade compatibility
Set up a staging environment that mirrors production
Review composer.json for outdated constraints
During Upgrade
Upgrade PHP to the target version first
Update composer.json to the next major constraint
Run composer update --with-all-dependencies
Run the CakePHP upgrade shell (bin/cake upgrade) if available
Update config/app.php and config/app_local.php
Rebuild schema cache: bin/cake schema_cache build
Run tests: vendor/bin/phpunit
After Upgrade
Verify all critical business flows in staging
Check error logs for deprecation warnings
Clear old cache directories manually
Run a full test suite and CI pipeline
Deploy to production in a maintenance window
Monitor logs and performance for 48 hours post-deploy

Version Upgrade Paths

Follow these steps in order. Each major version introduces fundamental changes that the next depends on.

2.x 3.x PHP 5.4 → PHP 5.6+

The biggest architectural leap. Entire framework was rewritten for PHP namespaces and Composer.

  • Namespaces: All classes moved to Cake\*
  • Composer: First-class dependency management
  • ORM: Completely rewritten (Table/Entity pattern)
  • Directory: app/ → src/
  • Views: .ctp kept but moved to src/Template/
  • Shells: Migrated to CakePHP 3.x Shell classes
  • Routes: Router::connect() → scoped routing
  • Auth: AuthComponent still present (updated API)
Use bin/cake upgrade shell (available in 2.x) to automate namespace migration.
3.x 4.x PHP 5.6+ → PHP 7.2+

Focus on PSR compliance, type safety, and dropping legacy PHP 5 baggage.

  • PSR-15: Middleware adopted standard interface
  • Datatypes: Strict boolean, integer, float DB types
  • PHP 7: Scalar type hints, return types required
  • Swoole: Experimental async support
  • Events: Overhauled with priority system
  • Validation: Fluent API deprecated in favor of nested
  • I18n: Message formatting improvements
  • Drop: PHP 5.x support removed
4.x 5.x PHP 7.2+ → PHP 8.1+

PHP 8.1 minimum, strict types everywhere, new plugin ecosystem.

  • PHP 8.1+: Enums, readonly properties, fibers
  • Strict types: Declare declare(strict_types=1) everywhere
  • Templates: .ctp → .php extension change
  • Authentication: Plugin replaces AuthComponent
  • Authorization: New cakephp/authorization plugin
  • Console: Shell classes → Command classes
  • Queue: Official cakephp/queue plugin
  • Drop: PHP 7.x support entirely

Composer Update

Incremental upgrade commands

Update your composer.json version constraint, then run:

# 2.x → 3.x
composer require cakephp/cakephp:^3.0 --with-all-dependencies

# 3.x → 4.x
composer require cakephp/cakephp:^4.0 --with-all-dependencies

# 4.x → 5.x
composer require cakephp/cakephp:^5.0 --with-all-dependencies

# After each upgrade step:
composer update
bin/cake cache clear_all
vendor/bin/phpunit
Always use --with-all-dependencies to avoid conflicting plugin constraints blocking the upgrade.
Commit the composer.lock before upgrading so you can revert with git checkout -- composer.lock && composer install.

Breaking Changes

Expand each section for details and migration examples.

The most disruptive change was in 3.x: all classes moved into PHP namespaces and directory structure flattened.

CakePHP 2.x
// app/Controller/ArticlesController.php
class ArticlesController extends AppController {
    public $uses = array('Article');
}
CakePHP 3.x+
// src/Controller/ArticlesController.php
namespace App\Controller;

class ArticlesController extends AppController {
    public function initialize(): void {
        parent::initialize();
        $this->loadComponent('Paginator');
    }
}
CakePHP 2.x used App::uses() for class loading. CakePHP 3.x+ uses Composer autoloading — no manual includes needed.

CakePHP adopted PSR-7 in 3.x and fully committed in 4.x.

Old (2.x / early 3.x)
$this->request->data
$this->request->params['pass']
$this->request->here()
PSR-7 (4.x / 5.x)
$this->request->getData()
$this->request->getParam('pass')
$this->request->getRequestTarget()

The ORM was completely rewritten in 3.x. Models became Table + Entity pairs.

CakePHP 2.x Model
class Article extends AppModel {
    public $uses = 'Article';
    public $belongsTo = array('Author');
    public $hasMany = array('Comment');

    public function findBySlug($slug) {
        return $this->find('first', array(
            'conditions' => array('slug' => $slug),
            'contain' => array('Author'),
        ));
    }
}
CakePHP 3.x+ Table + Entity
class ArticlesTable extends Table {
    public function initialize(array $config): void {
        $this->belongsTo('Authors');
        $this->hasMany('Comments');
    }

    public function findBySlug($slug) {
        return $this->find()
            ->contain(['Authors'])
            ->where(['slug' => $slug])
            ->first();
    }
}
In 5.x all entity accessors must use protected function _getXxx() with return type hints.

CakePHP 2.x
Router::connect('/blog/:slug',
    array('controller' => 'articles',
          'action' => 'view'),
    array('pass' => array('slug'),
          'slug' => '[a-z0-9-]+')
);
CakePHP 3.x+
$routes->connect('/blog/:slug',
    ['controller' => 'Articles',
     'action' => 'view'])
    ->setPass(['slug'])
    ->setPatterns(['slug' => '[a-z0-9-]+'])
    ->setName('article:view');

CakePHP 5.x replaces the built-in AuthComponent with the standalone cakephp/authentication and cakephp/authorization plugins.

AuthComponent (2.x – 4.x)
// AppController
public $components = ['Auth'];

// Controller
public function login() {
    if ($this->Auth->login()) {
        return $this->redirect(
            $this->Auth->redirectUrl()
        );
    }
}
Authentication Plugin (5.x)
// Application.php middleware
$service = new AuthenticationService();
$service->loadIdentifier(
    'Authentication.Password',
    ['fields' => ['username' => 'email']]
);
$service->loadAuthenticator(
    'Authentication.Session'
);
$service->loadAuthenticator(
    'Authentication.Form',
    ['loginUrl' => '/users/login']
);

CakePHP 5.x renames all template files from .ctp to .php.

Before (4.x)
templates/Articles/
  index.ctp
  add.ctp
  edit.ctp
templates/layout/
  default.ctp
After (5.x)
templates/Articles/
  index.php
  add.php
  edit.php
templates/layout/
  default.php

Simply rename your files. Template syntax and helper usage remain identical.

Database & ORM

Connection config

Connection configuration moved from app/Config/database.php to config/app_local.php.

// config/app_local.php (5.x)
'Datasources' => [
    'default' => [
        'className' => Cake\Database\Connection::class,
        'driver' => Cake\Database\Driver\Mysql::class,
        'host' => env('DB_HOST', 'localhost'),
        'username' => env('DB_USERNAME', 'root'),
        'password' => env('DB_PASSWORD', ''),
        'database' => env('DB_DATABASE', 'myapp'),
        'encoding' => 'utf8mb4',
        'cacheMetadata' => true,
    ],
],
Schema & Migrations
utf8mb4 is strongly recommended for all versions. CakePHP 5.x defaults to utf8mb4. Upgrade your tables before migrating. 
-- Convert existing tables
ALTER TABLE articles CONVERT TO CHARACTER SET utf8mb4
  COLLATE utf8mb4_unicode_ci;

-- Run pending migrations
bin/cake migrations migrate

-- Rebuild schema cache
bin/cake schema_cache build
ORM Query Evolution
2.x find()
$this->Article->find('all', [
    'conditions' => ['published' => 1],
    'contain' => ['Author'],
    'order' => ['created' => 'DESC'],
]);
3.x+ Query Builder
$this->fetchTable('Articles')
    ->find()
    ->contain(['Authors'])
    ->where(['published' => true])
    ->orderBy(['created' => 'DESC'])
    ->all();

Adopt New Features After Upgrade

Once your app is running on the latest version, leverage these modern capabilities.

Middleware Stack (PSR-15)

Replace component-based logic with reusable middleware classes for CORS, rate limiting, request logging.

// src/Application.php
$queue->add(new RoutingMiddleware($this))
      ->add(new BodyParserMiddleware())
      ->add(new CsrfProtectionMiddleware())
      ->add(new AuthenticationMiddleware($this));
Command Classes

CakePHP 5.x replaces Shell classes with modern Command classes with auto-wiring.

// src/Command/SendReportCommand.php
class SendReportCommand extends Command
{
    public function execute(Arguments $args, ConsoleIo $io): int
    {
        $io->out('Sending report...');
        return static::CODE_SUCCESS;
    }
}
Enums & Readonly Properties

PHP 8.1 features are fully supported. Use enums for status fields, readonly for DTOs.

enum ArticleStatus: string {
    case Draft = 'draft';
    case Published = 'published';
    case Archived = 'archived';
}
Queue / Job System

Offload slow tasks (emails, reports, webhooks) to background workers.

QueueManager::push(SendEmailJob::class, [
    'to' => 'user@example.com',
    'subject' => 'Welcome!',
]);
// bin/cake queue worker

Testing Strategy

Unit Tests

Test models, entities, and business logic in isolation.

vendor/bin/phpunit
  tests/TestCase/Model/
Integration Tests

Verify controller responses, redirects, and auth flows.

vendor/bin/phpunit
  tests/TestCase/Controller/
CI Pipeline

Run tests automatically on every push.

# GitHub Actions example
composer install
vendor/bin/phpunit
bin/cake cache clear_all
Before upgrading: ensure all tests pass on the current version. Then upgrade, fix failures incrementally.

Rollback Plan

If the upgrade fails in staging or production, follow this recovery procedure.

Code Rollback
# Revert all file changes
git checkout -- .

# Or restore a tagged version
git checkout tags/v2.8.0-stable

# Restore composer.lock
git checkout HEAD~1 -- composer.lock
composer install
Database Rollback
# Roll back all migrations
bin/cake migrations rollback -t 0

# Restore from SQL dump
mysql -u root -p myapp < backup_before_upgrade.sql
Always take a full database backup before upgrading. Use mysqldump or your RDS snapshot feature. Test the rollback process in staging first.

Common Pitfalls

2.x $this->data undefined

After upgrading to 3.x+, access post data via $this->request->getData().

3.x Missing intl extension

CakePHP 3.x+ requires the intl PHP extension. Install with apt install php-intl or equivalent.

4.x Plugin conflicts

Some 3.x plugins are not compatible with 4.x. Check each plugin's composer.json for require constraints.

5.x White screen on upgrade

Enable debug => true, check logs/error.log, clear all caches. Often a missing PHP 8.1 compatible extension.

Composer memory exhausted

Run COMPOSER_MEMORY_LIMIT=-1 composer update to disable memory limit.

Missing tmp/ writable

Ensure tmp/ and logs/ directories are writable by the web server user.

Performance Considerations

Schema Cache

Always rebuild schema cache after upgrading to avoid slow metadata queries.

bin/cake schema_cache build

# Clear if issues arise
bin/cake schema_cache clear
ORM Query Optimization

Review lazy loading after upgrade. Add contain() calls for all required associations.

// Before: N+1 queries
foreach ($articles as $a) {
    $a->author->name;
}

// After: eager load
$articles = $this->fetchTable('Articles')
    ->find()->contain(['Authors'])->all();

Debugging Tips

If you encounter a "White Screen of Death" or 500 error during upgrade:

  1. Enable debug => true in config/app.php.
  2. Check the logs in logs/error.log.
  3. Clear all caches using bin/cake cache clear_all.
  4. Verify that folder permissions for tmp/ and logs/ are correct.
  5. Run bin/cake schema_cache build to rebuild metadata cache.
  6. Check PHP version compatibility: php -v vs the version in composer.json.
  7. Run composer diagnose to check for dependency issues.
  8. Use php -l on migrated PHP files to detect syntax errors.
